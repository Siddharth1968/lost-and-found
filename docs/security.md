# Security model and limits

- Passwords: bcrypt cost 12; minimum 12 characters and maximum 72 UTF-8 bytes to avoid truncation. No default admin password or credentials in tracked files.
- Sessions: random 32-byte opaque token, SHA-256 stored in MySQL; HttpOnly + SameSite=Lax cookie; Secure and `__Host-` prefix in production. Expiry, current activation and current role checked per request. Logout/deactivation revoke server records. Tokens never go in localStorage.
- CSRF: exact configured Origin on all unsafe API requests, random HTTP-only CSRF cookie and matching custom header, hex/length validation and timing-safe comparison. Login/register are protected too. No credentialed cross-origin CORS. The app assumes no attacker-controlled content is hosted on its origin.
- Authorization: middleware protects admin routes; services enforce reporter ownership and legal workflow state. Students cannot assign roles; unknown/privileged input keys are rejected. Own claims and own listings cannot be reviewed by the same administrator.
- Validation: server Zod schemas for bodies, IDs, dates, filters and pagination. Prisma binds values; the only raw query uses tagged, parameterized SQL for a row lock. No client-provided SQL identifiers.
- Evidence: public list/detail projections omit identifiers and user contact data; reporter claim lists omit claimant evidence. Claimants see their own proof; admins see evidence for verification. Audit records have no passwords, tokens, proof or contact data. Notification text contains only item titles and workflow messages.
- Uploads: memory/file/field limits, maximum 5 MB, actual sharp decode and format verification, 25 megapixel limit, no SVG/executables, rotation, metadata stripping and fresh WebP encoding. UUID-only output filenames; deletion checks a strict server path pattern. Replaced files and failed DB writes are cleaned up. CSP/nosniff/disabled directory indexes and dotfiles prevent serving active upload content. A crash can leave an orphan; local storage is single-host and needs backups.
- Transport/browser: Helmet, restrictive production CSP, no third-party assets/scripts, generic server errors. HTTPS must be supplied by the production reverse proxy. Trust proxy only for one known hop.
- Rate limits: 30 authentication attempts/IP/15 minutes and 100 domain writes/IP/15 minutes; process memory storage, not shared across instances. In-memory limits reset when the process restarts. A production deployment must set realistic limits for a campus behind NAT.
- Database: separate credentials and database; FK/unique/CHECK constraints, consistent item lock order, atomic claim decisions and notification/audit writes. Runtime least-privilege grants should be separated from migration privileges. SQL operators are trusted; the API's domain state machine cannot protect against an operator with arbitrary SQL rights.
- Lifecycle: no password reset/email verification or multi-factor flow is in scope. College email suffix restriction checks the suffix, not email ownership; it is disabled by default. Administrators are provisioned by a local operator, and administrator accounts cannot be altered from the student-management screen.

The automated suite exercises authorization, CSRF/origin rejection, private projections, malformed/oversized images, constraints, concurrent approval and rollback. No external penetration test, malware scanning service, campus SSO integration or large-scale load test has been performed. Dependency audit findings are recorded in the verification report.
